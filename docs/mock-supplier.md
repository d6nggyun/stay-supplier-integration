# Mock Supplier 설계

## 1. 목적

Mock 공급사는 정교한 상품 데이터를 만드는 것이 아니라, 연동 흐름의 정상·실패·무응답을 재현하는 것이 목적입니다. 따라서 Mock 자체의 복잡도는 낮게 유지합니다.

## 2. 별도 모듈·별도 포트

Mock 공급사는 본 애플리케이션과 별도 모듈로 분리하고 포트 `9090`을 사용합니다.

같은 포트를 쓰면 애플리케이션이 자기 자신의 HTTP 서버를 공급사로 호출하는 구조가 되어, 스레드가 묶이면서 실제 외부 연동 문제와 구분하기 어려워집니다. 그래서 모듈과 포트를 분리합니다.

## 3. 재현 상태

Mock은 다음 상태를 지원합니다.

```
normal       정상 응답
error        공급사 장애
no-response  무응답
```

### 정상

- Supplier A: 정상 응답
- Supplier B: 정상 응답

### 장애

- Supplier A: HTTP 503
- Supplier B: HTTP 200 + `resultCode: E503`

두 공급사의 실패 표현 방식이 다르다는 점을 그대로 재현해, 어댑터의 실패 판정 통일([supplier-adapter.md](supplier-adapter.md))이 실제로 동작함을 확인할 수 있게 합니다.

### 무응답

연결은 성공하지만 일정 시간 응답하지 않습니다. 이를 통해 응답 타임아웃과 부분 실패 처리를 검증합니다.

## 4. 상태 전환

상태는 런타임에 전환할 수 있도록 제어 엔드포인트를 둡니다. 예: `POST /control/{a|b}/mode?value=normal|error|no-response`. 이렇게 하면 하나의 Mock 인스턴스로 정상·장애·무응답 시나리오를 차례로 검증할 수 있습니다.
