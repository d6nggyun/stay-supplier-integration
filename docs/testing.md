# 테스트 전략

테스트는 도메인 규칙, 어댑터 변환, 검색 오케스트레이션, API 계약의 네 층으로 나눕니다. 타임아웃·지연 시나리오는 MockWebServer로 재현합니다.

## 1. 도메인 단위 테스트

- 숙박일수 계산 (체크아웃일 제외)
- 날짜별 재고의 최솟값 계산
- 하루 재고가 0일 때 예약 가능 객실 수가 0이 되는지 확인
- 세전 금액과 세금 합산으로 세금 포함 총액 산출
- 세금 포함 총액을 그대로 사용하는 경우 처리
- 총액 기준 1박 평균가 계산
- 소수점 이하 내림 처리
- 통화 환산 없이 코드 보존
- 조식 포함 여부 보존

## 2. 어댑터 테스트

- Supplier A 정상 응답 변환
- Supplier A HTTP 503 변환
- Supplier B 정상 응답 변환
- Supplier B HTTP 200 + 실패 코드 변환
- 잘못된 응답 형식 처리

## 3. 검색 서비스 테스트

- 두 공급사 모두 성공
- 한 공급사 실패 후 다른 공급사 결과 반환 (양방향)
- 한 공급사 무응답 시 타임아웃 후 다른 결과 반환
- 두 공급사 모두 실패 시 5xx로 응답하되 본문에 공급사별 상태 포함
- 매핑이 없는 공급사가 `SKIPPED`로 표기되는지 확인
- 50개 초과 코드가 청크로 분할되는지 확인
- 공급사 코드가 내부 식별자로 변환되는지 확인

## 4. API 통합 테스트

- 정상 검색 요청
- 잘못된 날짜 범위
- 잘못된 인원 값
- 예약 불가 상품을 `0`으로 노출
- 부분 실패 시 HTTP 200 응답
- 응답에 공급사 원본 코드가 아닌 내부 식별자가 포함되는지 확인

> 카탈로그(①) 동기화 실패 정책(기존 매핑 지속 / 공급사 제외)의 Mock 장애 모드와 검증 테스트는 설계로만 남기고 구현·검증은 후순위로 둡니다. ([mapping.md](mapping.md#동기화-실패-처리) 참고)
