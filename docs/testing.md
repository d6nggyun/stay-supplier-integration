# 테스트 전략

테스트는 도메인 규칙, 어댑터 변환, 검색 오케스트레이션, API 계약의 네 층으로 나눕니다. 타임아웃·지연 시나리오는 MockWebServer로 재현합니다.

## 0. 테스트 층위와 선택 근거

각 대상의 성격에 맞는 **가장 가벼운 도구**를 골라, 아래(단위)는 두껍고 위(전체 통합)로 갈수록 얇은 피라미드 형태로 둡니다. 느리고 깨지기 쉬운 상위 테스트를 최소화하면서, 목(mock)으로는 드러나지 않는 실제 동작은 반드시 실물로 한 번 검증하는 것이 원칙입니다.

| 층위 | 도구 | 대상 | 왜 이 층위인가 |
| --- | --- | --- | --- |
| 순수 단위 | 목(Mockito), 스프링·I/O 없음 | 도메인 계산·검증, 오케스트레이터·동기화 **로직**, 타임아웃 판정 유틸 | 분기·경계값이 많은 순수 로직은 컨텍스트 없이 빠르게 많이 돌리는 것이 이득입니다. 협력자(어댑터·리포지토리)는 목으로 끊어 로직만 격리합니다. |
| 컴포넌트(narrow) | 실제 `WebClient` ↔ MockWebServer, 스프링 없음 | 공급사 어댑터 | 어댑터의 본질은 **실제 HTTP 응답의 역직렬화·요금 합산·실패 판정**입니다. 목으로 바꾸면 정작 검증할 변환이 사라지므로, 실제 WebClient로 loopback HTTP를 태우되 컨텍스트는 띄우지 않아 가볍게 유지합니다. |
| 슬라이스 | `@DataJpaTest` / `@WebMvcTest` | 리포지토리(+실제 H2), 컨트롤러 MVC 계약 | 영속·웹 계층은 프레임워크 동작(유니크 제약, 파라미터 바인딩, 상태 코드, 직렬화)이 핵심이라 실물 일부가 필요합니다. 다만 전체 컨텍스트 대신 해당 계층만 부분 기동해 비용을 줄입니다. 협력 서비스는 목으로 끊습니다. |
| 전체 통합(e2e) | `@SpringBootTest`(랜덤 포트) + MockWebServer + 실제 H2 | 컨트롤러 → 오케스트레이터 → 실제 WebClient → 공급사 대역 → DB | `.timeout()`·병렬·부분 실패·DTO 직렬화처럼 **계층이 맞물려야만 드러나는 동작**은 목 조합으로는 확신할 수 없어, 전 계층을 한 번에 태워 확인합니다. 느리므로 대표 시나리오만 소수 둡니다. |

즉 "무엇을 검증하려는가"가 도구를 정합니다. 로직은 단위로, 실제 HTTP 변환은 컴포넌트로, 프레임워크 계약은 슬라이스로, 계층 상호작용은 전체 통합으로 확인합니다.

## 1. 도메인 단위 테스트

- 숙박일수 계산 (체크아웃일 제외)
- 날짜별 재고의 최솟값 계산
- 하루 재고가 0일 때 예약 가능 객실 수가 0이 되는지 확인
- 세전 금액과 세금 합산으로 세금 포함 총액 산출
- 세금 포함 총액을 그대로 사용하는 경우 처리
- 총액 기준 1박 평균가 계산
- 소수점 이하 내림 처리
- 통화 환산 없이 코드 보존
- 조식 포함 여부 보존

## 2. 어댑터 테스트

- Supplier A 정상 응답 변환
- Supplier A HTTP 503 변환
- Supplier B 정상 응답 변환
- Supplier B HTTP 200 + 실패 코드 변환
- 잘못된 응답 형식 처리

## 3. 검색 서비스 테스트

- 두 공급사 모두 성공
- 한 공급사 실패 후 다른 공급사 결과 반환 (양방향)
- 한 공급사 무응답 시 타임아웃 후 다른 결과 반환
- 두 공급사 모두 실패 시 5xx로 응답하되 본문에 공급사별 상태 포함
- 매핑이 없는 공급사가 `SKIPPED`로 표기되는지 확인
- 50개 초과 코드가 청크로 분할되는지 확인
- 공급사 코드가 내부 식별자로 변환되는지 확인

## 4. API 컨트롤러 테스트 (슬라이스)

`@WebMvcTest`로 서비스는 목(mock) 처리하고 컨트롤러 계약만 검증합니다.

- 정상 검색 요청 (200, 내부 전용 필드 미노출)
- 잘못된 날짜 범위·필수 파라미터 누락·형식 오류 (400)
- 호출한 공급사 전부 실패 (502), 전부 `SKIPPED` (503) — 본문에 공급사별 상태 포함
- 수동 동기화 트리거 (200)

## 5. 전체 스택 통합 테스트

`@SpringBootTest`(랜덤 포트) + MockWebServer로 컨트롤러 → 오케스트레이터 → **실제 WebClient** → 공급사 대역을 태워, 목으로는 확인할 수 없는 실제 동작을 검증합니다. 매핑은 DB에 직접 심어 검색 경로만 격리합니다.

- 두 공급사 정상 → 200, 결과 병합, 내부 식별자 치환
- 한 공급사 응답 지연 → **실제 응답 타임아웃**으로 `TIMEOUT`, 나머지 공급사 결과로 200 (부분 실패)
- 매핑 없음 → 503

`TimeoutClassifier`(연결·읽기 타임아웃 판정)는 원인 사슬 순회·자기참조 방어를 단위 테스트로 고정합니다.

> 카탈로그(①) 동기화 실패 정책(기존 매핑 지속 / 공급사 제외)의 Mock 장애 모드와 검증 테스트는 설계로만 남기고 구현·검증은 후순위로 둡니다. ([mapping.md](mapping.md#동기화-실패-처리) 참고)
