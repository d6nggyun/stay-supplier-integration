# 통합 숙박 상품 모델

서로 다른 두 공급사의 표현을 흡수하는 내부 표준 모델을 정의합니다. 무엇을 공통 기준으로 삼고 무엇을 버리는지, 그 근거를 함께 기록합니다.

## 1. 검색 조건

```
SearchCriteria
- checkIn
- checkOut
- adults
- children
```

날짜 경계는 체크아웃일을 숙박일에 포함하지 않습니다. 예를 들어 `2026-09-01`부터 `2026-09-04`까지는 3박입니다.

```
long nights = ChronoUnit.DAYS.between(checkIn, checkOut);
```

검색 조건은 다음과 같이 검증합니다.

- `checkIn`은 `checkOut`보다 이전이어야 합니다.
- `adults`는 0보다 커야 합니다.
- `children`은 0 이상이어야 합니다.
- 인원 값은 음수가 될 수 없습니다.

인원 수용 여부(`adults + children <= maxOccupancy`)는 공급사가 조회 시 걸러 반환하므로, 우리 쪽에서 별도로 필터링하지 않습니다.

## 2. 표준 검색 결과

내부 도메인에서는 검색 결과를 `StayOffer`로 표현합니다.

```
StayOffer
- internalStayId
- stayName
- internalRoomTypeId
- roomTypeName
- maxOccupancy
- availableRoomCount
- supplier
- breakfastIncluded
- price
- dailyAvailability
```

`dailyAvailability`는 날짜별 재고를 제공하는 공급사의 경우 내부 모델에 보존합니다. 다만 검색 목록 응답에서는 공급사 간 응답 구조를 동일하게 유지하기 위해 날짜별 정보를 직접 노출하지 않습니다.

## 3. 요금 모델

고객에게 제공하는 요금 기준은 **세금 포함 총액**입니다.

```
Price
- currency
- grossTotalAmount
- averageNightlyAmount
```

### 공통 기준을 세금 포함 총액으로 잡은 이유

한 공급사는 날짜별 세전 단가와 세액을 따로 제공하고, 다른 공급사는 세금이 포함된 숙박 전체 총액만 제공하며 날짜별 요금과 세액을 분리해 주지 않습니다. 두 공급사가 모두 만들 수 있는 유일한 공통 분모가 세금 포함 총액이므로 이를 기준으로 통일합니다.

### 총액 산출

세전 단가와 세액을 따로 주는 공급사는 날짜별로 합산합니다.

```
grossTotalAmount = Σ(nightlyRate + taxAmount)
```

세금 포함 총액만 주는 공급사는 그 값을 그대로 사용합니다.

```
grossTotalAmount = totalPrice
```

### 1박 평균가

1박 평균가는 표시용 파생 값입니다.

```
averageNightlyAmount = grossTotalAmount / nights   // 소수점 이하 버림(내림)
```

- 두 값을 모두 내려주는 이유는, 사용자가 숙소를 비교할 때는 1박 기준으로 가늠하고 실제 지불 금액은 총액으로 판단하기 때문입니다. 하나만 주면 나머지를 클라이언트가 계산해야 합니다.
- 나누어떨어지지 않으면 내림합니다. 올림은 실제보다 비싸 보이므로 택하지 않습니다.
- 총액이 원본이고 평균가는 표시용 파생 값이므로, `평균가 × 박수 ≠ 총액`이 되는 오차를 허용합니다.

### 통화

통화는 환산하지 않고 공급사가 제공한 ISO 4217 코드를 그대로 사용합니다. 환산은 환율 소스 결정이 필요해 이번 범위를 벗어납니다.

## 4. 재고 모델

재고는 날짜별 잔여 객실 수를 기반으로 계산합니다.

```
availableRoomCount = min(각 숙박일의 remainingRooms)
```

연박 전체를 예약할 수 있어야 하므로, 하루라도 재고가 0이면 예약 가능 객실 수는 0입니다.

예약 불가 상품은 검색 응답에서 제거하지 않고 `availableRoomCount: 0`으로 노출합니다. 그래야 재고 판정 결과를 응답으로 확인할 수 있고, 상품이 검색되지 않은 이유를 추측하지 않아도 됩니다.

## 5. 조식 정보

조식 포함 여부는 요금에 흡수하지 않고 별도 필드로 제공합니다. 같은 객실 타입이라도 공급사에 따라 조식 포함 여부가 다를 수 있어, 이를 제거하면 가격 비교의 전제가 달라집니다.

## 6. 버린 정보와 그 근거

| 정보 | 처리 | 근거 |
| --- | --- | --- |
| 날짜별 요금 | 내부 모델에 보존, 응답에서 제외 | 응답 형태를 공급사 간 일치시키되 정규화·확장 여지를 남기기 위함입니다. |
| 세액 분리 | 버림 | 한 공급사가 세액을 분리해 주지 않아 공통으로 만들 수 없습니다. |
| 통화 환산 | 하지 않음 | 환율 소스 결정이 필요해 범위를 벗어납니다. |
| 개별 물리 객실 번호 | 노출하지 않음 | 공급사가 객실 타입 단위로만 재고·요금을 제공합니다. |
